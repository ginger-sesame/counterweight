## Interface and ownership contract for Phase 2

- `contracts/libraries/StrategyTypes.sol`: shared Solidity structs, canonical token identities, unit/envelope constants, and named errors. Keep ABI field order/types stable or document and revalidate consumers.
- `InventoryGuard.validateConfig`: canonical pair, authority, epoch, price, amount cap, and strictly ordered bounds. Called by constructor before activation.
- `InventoryGuard.checkBacking` and `checkSize`: numerical envelopes/physical availability and exact notional cap before pricing. `checkPost` is the independent exposure decision; its configuration must already be validated. It deliberately takes no tuning.
- `QuoteMath.boundedTuning`: available valid values pass; missing/out-of-range inputs become `{available:false,intensityBps:0,spreadBps:100}`. Unknown safety fields cannot be represented in the Solidity tuning struct.
- `QuoteMath.calculate`: internal pure function with preconditions—validated configuration, inventory envelope, positive size-limited input and bounded tuning. Output is not an authorization to settle; the guard must subsequently pass.
- `StrategyPrototype.quote(Inventory, Request, Tuning)`: validates mode/token/epoch, numerical envelope/backing/size; computes quote; rejects zero/insufficient output; projects balances and applies the hard guard. It returns amountOut, postWeth, postUsdc, displayed weightBps, signed skewBps, and effectiveTuning. `checkPost(weth,usdc)` exposes the same guard for direct testing.
- Safety is constructor-only storage plus `safetyDigest = keccak256(abi.encode(config))`; no setters, delegatecall or custody functions. `owner` identifies the planned authority, but this prototype has no privileged operations to authorize.

Inventory fields are allocated WETH wei/USDC base units and separately supplied physical balances. Price is micro-USDC per whole WETH; all balances and inputs are raw integer base units <=10^30. The maker retains the entire input. Exact-input only; partial fills/native ETH/additional transfer fees are unsupported. Post-state exposure uses exact cross multiplication, while the displayed pre-state weight uses floor division. See ACCOUNTING for the full formulas and rejection order.

`config/prototype.json` is the runnable config schema/example: all integers are canonical unsigned decimal strings, addresses are Ethereum addresses, every field is required, and extra fields are rejected. Width checks precede ABI encoding; economic constraints are enforced in Solidity. `start`/`end` are Unix seconds; the runner initializes its local clock from `start`. This historical fixture timestamp does not activate a live epoch.

## Runner and evidence contract

CLI options: `--config <json>`, `--fixtures <accounting-json>`, `--out <json>`. Defaults are repository paths, independent of caller cwd. Output parent directories must already exist. Overrides `FORGE_BIN`/`ANVIL_BIN` accept executable paths. There is no external RPC option. Builds have a 120-second timeout, readiness is bounded, receipts have a 10-second timeout, and E2E invocations have a 45-second timeout. The runner terminates its Anvil on success and caught errors.

Each report labels `simulated:true`, `tokenSettlement:false`, local chain 31337, config, source hashes, revision when Git metadata exists, UTC run time, local deployment identity, safety digests, and all outcomes. Accepted outcomes include quote/projected balances. Rejections include the named Solidity error and unchanged projected balances. Assertions compare normal outputs against fixed expected values and independently bound accepted post-state. Missing/adversarial regimes must change the selected target quotes, retain fallback caps, and reject the unsafe cases. Failures produce JSON on stderr and exit 1; no new passing artifact is written. Use a fresh output path per evidence run to avoid mistaking an older file for new results.

Fixtures are an assertion suite, not arbitrary market requests. It must include target successes and exposure failures in both directions. The standard fixture has 16 cases. Changing its economics requires an independently reviewed expectation update, not copying output from the implementation. Failed golden cases have their intermediate amounts checked by the Solidity math harness; the public pipeline returns only a rejection.
